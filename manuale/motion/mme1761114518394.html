MC_CamInCurve

The MC_CamInCurve instruction starts a cam operation based on the CamProperty (Cam Properties) and CamNodes (Cam Nodes) specified in the In-Out variables.

It performs a smoother cam operation compared to the MC_CamIn (Start Cam Operation) instruction as it interpolates between cam nodes using a specified curve.

Function

The MC_CamInCurve instruction executes the cam operation by calculating the displacement (slave axis) corresponding to the phase (master axis) based on the CamProperty (Cam Properties) and CamNodes (Cam Nodes) values specified in the in-out variables when Execute changes to TRUE.

The command position for the slave axis is calculated by interpolating the displacement (slave axis) corresponding to the phase (master axis) with a specified curve between two node points.





During execution of this instruction, rewriting the contents of the CamNodes (Cam Nodes) and/or CamProperty (Cam Properties) in-out variables in the user program is not reflected in the instruction. To have changes made to the CamNodes (Cam Nodes) or CamProperty (Cam Properties) reflected during execution of this instruction, restart the instruction after making the changes.

You cannot use the MC_CamMonitor (Cam Monitor) instruction to monitor the cam operation of this instruction. To monitor the cam operation of this instruction, use the MC_CamMonitorCurve (Cam Monitor With Specified Curve) instruction.

If the absolute value of the product of the cam profile curve displacement and the SlaveScaling (Slave Axis Coefficient) exceeds the 40-bit data range when it is converted into pulses, a Cam Operation Displacement Overflow error (error code: 5758 hex) will occur. If a Cam Operation Displacement Overflow error (error code: 5758 hex) occurs, the instruction will stop without updating the command position of the slave axis.

Cam Operation Displacement Overflow

A Cam Operation Displacement Overflow error occurs if the cam profile curve displacement or the SlaveScaling (Slave Axis Coefficient) is too large.

Adjust the Distance (Slave Axis Displacement) of CamNodes and the SlaveScaling (Slave Axis Coefficient) so that the absolute value of the product of the cam profile curve displacement and the SlaveScaling (Slave Axis Coefficient) does not exceed the 40-bit data range when it is converted to pulses.

If the Curve (Curve Shape) is a polynomic 3 or polynomic 5 curve, the InitVel (Initial Velocity) and InitAcc (Initial Acceleration) cam property variables as well as the ConnectingVel (Connecting Velocity) and ConnectingAcc (Connecting Acceleration) cam node variables are also related. Refer to the following calculation methods for displacement of the polynomic 3 or polynomic 5 curve and correct the values in the CamProperty (Cam Properties) and CamNodes in-out variables.

When executed or re-executed, this instruction checks if the phases are in ascending order. If the phases are not in ascending order, a Cam Node Master Axis Phase Not in Ascending Order error (error code: 5740 hex) occurs.

If you change the values of cam node variables or cam property variables from more than one task, program the changes so that there is no race condition in writing the value from more than one task.

If a cam node variable or cam property variable is switched by re-executing the instruction during a cam motion, the velocity or acceleration of the slave axis may change rapidly before or after the cam table is switched. Since this may affect the mechanical machine, be sure to thoroughly verify that there will be no excessive changes in velocity or acceleration before switching the cam node variable or cam property variable.

Relation to MC_CamIn Instruction

Unlike the MC_CamIn (Start Cam Operation) instruction, the MC_CamInCurve instruction uses cam definition variables (cam node variables and cam property variables) as input variables.

Cam definition variables contain data on points and a curve shape between the points with respect to phase and displacement. The Sysmac Studio Cam Editor or the MC_GenerateCamTable instruction discretizes the cam definition variable data into a cam table for use with the MC_CamIn instruction.

Due to use of cam definition variables as input variables, this instruction provides the following improvements compared to the MC_CamIn (Start Cam Operation) instruction.

  • There is no need to wait for completion of cam table generation by the MC_GenerateCamTable (Generate Cam Table) instruction.
  • More precise slave axis command values can be output because cam definition variables are not discretized by phase pitch.


Instruction Details

This section describes the instruction in detail.

Instruction Execution Condition

You can execute this instruction while the master axis is stopped, during position control, velocity control, or synchronized control.

For details on the slave axis, refer to ☆MC_CamInCurve and ☆MC_CamInCurve .

Software Limits

If the slave axis exceeds the software limit during cam operation, an error occurs.

Cam Node Variables

For details on cam node variables, refer to ☆MC_GenerateCamTable.

Unlike the MC_GenerateCamTable (Generate Cam Table) instruction, the MC_CamInCurve instruction does not round the Phase (Master Axis Phase), Distance (Slave Axis Displacement), ConnectingVel (Connecting Velocity), and ConnectingAcc (Connecting Acceleration) values of cam node variables to the fourth decimal place. However, the Sysmac Studio Cam Editor does not allow you to specify the fourth decimal place or beyond. To specify the fourth decimal place or beyond, use cam node variables that are defined as user-defined variables.

Specify the values of Phase (Master Axis Phase) so that the difference in Phase (Master Axis Phase) between the cam nodes is greater than 0.001. If the difference in Phase (Master Axis Phase) is less than 0.001, a Cam Node Master Axis Phase Not in Ascending Order error (error code: 5740 hex) occurs.

This instruction does not use the value entered in PhasePitch (Phase Pitch).

Cam Property Variables

For details on cam property variables, refer to ☆MC_GenerateCamTable.

Unlike the MC_GenerateCamTable (Generate Cam Table) instruction, the MC_CamInCurve instruction does not round the InitVel (Initial Velocity), InitAcc (Initial Acceleration), and CycleTime (Cycle Time) values of cam property variables to the fourth decimal place. However, the Sysmac Studio Cam Editor does not allow you to specify the fourth decimal place or beyond. To specify the fourth decimal place or beyond, use cam property variables that are defined as user-defined variables.

For this instruction, you can specify 0 for CycleTime (Cycle Time). If you specify 0, the instruction recognizes the InitVel (Initial Velocity) and InitAcc (Initial Acceleration) cam property variables and the ConnectingVel (Connecting Velocity) and ConnectingAcc (Connecting Acceleration) cam node variables as values based on the master axis phase.

For example, velocity based on the master axis phase refers to the amount of change in the slave axis displacement relative to the travel distance of the master axis phase.

Starting Cam Operation

After instruction execution, the instruction waits for the master axis to reach StartPosition (Cam Nodes Start Position).

After the master axis passes the StartPosition (Cam Nodes Start Position), the start point of the cam nodes is executed and the InCam output variable (Cam Motion) changes to TRUE.

Since the phase and displacement of the cam nodes are given as relative values with the start point as zero, the absolute position of each axis at each phase is a relative value originating from the absolute position of each axis at the start of the cam nodes. For example, suppose the Count Mode of the master axis is Rotary Mode (0° to 360°) and the StartPosition (Cam Nodes Start Position) is 60. The absolute position of the master axis is the phase of the cam nodes added by the StartPosition value and the absolute position of the slave axis is the displacement of the cam nodes added by the absolute position of the slave axis at the start of the cam nodes.



Then, when the master axis passes the MasterStartDistance (Master Following Distance), the cam operation of the slave axis starts and the InSync output variable changes to TRUE.

The MasterStartDistance (Master Following Distance) is specified either as an absolute position or as a relative distance from the StartPosition (Cam Nodes Start Position). Set whether to specify an absolute position or relative position in StartMode.

EndOfProfile (End of Cam Cycle)

EndOfProfile (End of Cam Cycle) is TRUE for one period when the command value of the cam motion for the phase and displacement defined by the end point of the CamNodes (Cam Nodes) is output.

Set the absolute position of the master axis as the StartPosition (Cam Nodes Start Position) and the CamNodes (Cam Nodes) becomes relative to that position.

EndOfProfile (End of Cam Cycle) functions as an output indicating the end of the CamNodes (Cam Nodes).

Ending Cam Operation

Use the MC_CamOut (End Cam Operation) instruction or MC_Stop instruction to stop cam operation before it is completed.

Scaling Factor

You can specify a scaling factor to scale up or scale down the master axis phase and slave axis displacement of a specified CamNodes (Cam Nodes).

You can apply separate factors to the master and slave axes.

For details, refer to ☆MC_CamIn.

Offset

You can shift the phase and displacement by an offset from the specified CamNodes (Cam Nodes).

You can specify separate offsets for the master axis phase and slave axis displacement.

For details, refer to ☆MC_CamIn.

ReferenceType (Position Type Selection)

Any of the following position types can be selected for the master axis to which the slave axis is synchronized.

  • _mcCommand: Command position (value calculated in the previous task period)

    The master axis command position that was calculated in the previous task period is used for the current period.

    The command value that was calculated for the master axis in the last periodic task is used to calculate the command position of the slave axis in the current period.

  • _mcFeedback: Value obtained in the same task period

    The actual position of the master axis that was obtained in the same task period is used.

  • _mcLatestCommand: Command position (value calculated in the same task period)

    The command position of the master axis that was calculated in the same task period is used.

    This enables the use of information that is more recent than for _mcCommand. However, the axis number of the master axis must be set lower than the axis number of the slave axis.

    If the axis number of the slave axis is lower than the axis number of the master axis, Error will change to TRUE. A Master/Slave Axis Numbers Not in Ascending Order error (error code: 5438 hex) will be output to ErrorID.

use:

Here, the task period is the primary period if the task is the primary periodic task and the task period of the priority-5 periodic task if the task is the priority-5 periodic task. In the same way, the periodic task is the primary periodic task or the priority-5 periodic task.

memo:

The command position that is calculated in the same task period enables greater precision in synchronization than the command position that was calculated in the previous task period.

However, the axis number set for the Master (Master Axis) in the system-defined variable for motion control must be lower than the axis number set for the Slave (Slave Axis) in the system-defined variable for motion control.

Aborting the Instruction

If an axis error occurs for the slave axis during execution of this instruction, the slave axis decelerates to a stop at the maximum deceleration rate for the axis. If the MC_Stop instruction is executed for the slave axis, CommandAborted changes to TRUE and the slave axis decelerates to a stop at the deceleration rate that is specified in the MC_Stop instruction.

Refer to the NJ/NX-series Troubleshooting Manual (Cat. No. W503) for information on isolating the causes of axis errors.

If an axis error occurs on the master axis, cam operation will continue.



Re-execution of Motion Control Instructions

You can re-execute this instruction to change the CamNodes (Cam Nodes) and CamProperty (Cam Properties) in operation. To change any conditions other than the CamNodes (Cam Nodes) and CamProperty (Cam Properties), use multi-execution of instructions for this instruction.

When re-executing the instruction, InCam and InSync retain the status that they had prior to the re-execution.

Only the CamNodes (Cam Nodes) and CamProperty (Cam Properties) are affected by re-execution.

use:

If a cam node variable or cam property variable is switched by re-executing the instruction during a cam motion, the velocity or acceleration of the slave axis may change rapidly before or after the cam table is switched.

Be careful when re-executing the instruction because the mechanical composition may be affected.

For details on re-execution of motion control instructions, refer to the NJ/NX-series CPU Unit Motion Control User’s Manual (Cat. No. W507).

Execution of Other Instructions during Instruction Execution

To use multi-execution of axis command instructions for this instruction, specify the slave axis.

When multi-execution of another instruction is performed while this instruction is in execution, the following limits apply depending on the Buffer Mode.

  • When another instruction is executed by using multi-execution with the Buffer Mode set to Aborting, the cam motion is aborted and the next operation is started.

  • When another instruction is executed with the Buffer Mode set to Buffered, the command value for the next operation is output when EndOfProfile (End of Cam Cycle) changes to TRUE.

Multi-execution of the MC_CamInCurve Instruction with Blending

  • You can specify Blending only for multi-execution of the MC_CamInCurve instruction. You cannot execute this instruction with Blending during execution of other instructions, including the MC_CamIn (Start Cam Operation) instruction.

  • Specify the same values for Master (Master Axis) and ReferenceType (Position Type Selection) as those specified in the instruction that is currently in operation. If you specify different values, a Motion Control Instruction Multi-execution Disabled error will occur.

  • The InSync output variable from the buffered instruction changes to TRUE in the period in which the current instruction is completed normally, and cam operation starts without the slave axis ever stopping.

  • Even if StartPosition (Cam Nodes Start Position) and MasterStartDistance (Master Following Distance) are specified, the slave axis starts cam operation as soon as instruction execution starts regardless of the values that are specified. The starting point in the CamNodes (Cam Nodes) is the final position for the current instruction. The operation is the same regardless of which of the four types of blending is specified.

Execution during Execution of Other Instructions

You can switch to this instruction or buffer this instruction if you execute it during execution of another instruction. You can buffer one instruction per axis.

Specify the operation of this instruction using BufferMode (Buffer Mode Selection) for multi-execution of instructions. For details, refer to ☆MC_CamIn.

If multi-execution of instructions causes any synchronized control instruction other than the MC_CamIn (Start Cam Operation) and MC_CamInCurve (Start Cam Operation With Specified Curve) instructions to be aborted (i.e., if the CommandAborted output variable changes to TRUE), any instructions that shift the phase are also aborted as CommandAborted changes to TRUE.

If blending is used for multi-execution of the MC_CamInCurve (Start Cam Operation With Specified Curve) instruction, any instances of the instruction that shift the phase are not aborted as CommandAborted does not change to TRUE, and processing is continued.

Errors

If an error occurs during execution of this instruction, Error will change to TRUE.

You can find out the cause of the error by referring to the value output by ErrorID (Error Code).

Depending on ErrorID (Error Code), attached information is output to ErrorParameterCode (Parameter Detail Code) and ErrorNodePointIndex (Error Node Point Element Number).
